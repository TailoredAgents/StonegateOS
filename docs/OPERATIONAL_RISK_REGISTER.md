# StonegateOS Operational Risk Register

> Active program risk register for alignment and prospect-demo work. Review before each production-affecting phase and update when ownership, mitigation, or evidence changes.

| Risk                                                      | Impact                                              | Current control                                              | Required phase gate                                                                    | Status                                                        |
| --------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| Production data reset, truncation, or accidental reseed   | Critical business interruption/data loss            | Explicit no-reset contract; E2E uses isolated services       | Verify every DB command/URL before execution; no live destructive commands             | Controlled by policy; live evidence open                      |
| E2E Compose project collides with another checkout         | Unrelated local containers or volumes removed        | Runner fixes the project name to `stonegateos-e2e`           | Verify project labels before volume cleanup; use only the disposable named stack        | Mitigated locally; source guard implemented                   |
| Destructive or incompatible migration                     | Critical deployment/data risk                       | Targeted migration runner and explicit `DB_MIGRATION_TARGET` | Additive review, isolated migration test, backup/rollback evidence                     | Deployment docs corrected; evidence open                      |
| Site/API/worker revision mismatch                         | Incorrect rules or duplicate/missed effects         | Readiness checks and recorded prior incident                 | Capture all deployed revisions and verify compatibility after deploy                   | Open                                                          |
| Mobile regression from desktop alignment                  | Daily crew disruption and stakeholder loss of trust | Mobile stability contract and separate mobile components     | Jeffrey review, 320/375 baselines, mobile regression tests                             | Baselines open                                                |
| Desktop/mobile permission mismatch                        | Unauthorized action or legitimate user blocked      | Server-side permission checks                                | Capability matrix, role tests, Expenses/job parity review                              | Known Expenses gap                                            |

| Live customer data appears in prospect demo               | Privacy and trust harm                              | Sanitized-demo policy                                        | Controlled dataset/account and pre-demo review                                         | Open                                                          |

## Review rule

A risk may move to closed only when its control is implemented and the required runtime, operational, or deployment evidence is linked. Documentation or source inspection alone cannot close a production/provider risk.
