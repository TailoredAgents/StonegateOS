## Additional implementation

- Staff can configure named crew/equipment resources and deliberately select them during CRM scheduling and partner review/reschedule acceptance. The same locked capacity checks and persisted resource snapshots protect automatic assignment and manual selections. Legacy public availability readers now filter their candidates through a bounded shared occupancy snapshot rather than their own weaker capacity rules.
- Staff payment reconciliation accepts an explicit, complete multi-payment allocation/refund plan with supporting evidence and a reason. It previews the result and applies the entire correction atomically using a revision and idempotency key. Original payments, job prices and commissions are preserved; immutable correction evidence explains the allocation change. Migration `0171_partner_payment_allocation_reconciliation` is additive.
- Historical cash/check principal missing from canonical records can be repaired only with a genuine past receipt, explicit allocations, evidence and a reason. This records already-received money, not a new collection or settlement notification. It cannot fund more than the unexplained recorded legacy paid principal. The staff member must affirm there is no unrecorded tip; missing tips require payroll review, and missing Square payments require provider reconciliation. Original job totals, rates and payouts are not rewritten.
- A partial canonical allocation no longer erases unexplained historical paid amounts during normal projection. Legitimate refund reductions still use gross settled principal as their backing. Statement refunds validate the whole split, then include only the invoices belonging to the statement period; a later-issued invoice's portion cannot inflate an earlier statement's refund total.
- Real invitation journeys exposed and corrected defects that a successful HTTP response alone did not prove: activation session hashes now use the canonical authentication encoding, and server-side invitation inspection no longer depends on the public marketing origin. Inspection forwards bounded, validated client address metadata only according to the existing trusted-proxy hop setting. Unavailable invitation configuration stays a retryable unavailable response rather than a false identity-conflict response.
- Suspending the selected company now fails closed instead of silently authorizing the identity against another company. Switching remains an explicit user action. An opaque mobile navigation background fixes contrast that varied with content beneath the former translucent background.
- Home totals use complete authorized records. Unscheduled review requests use their actual stored statuses and appear on Home without an invented arrival window. Integration fixtures cover more than 100 invoices, scoped totals and operational users' financial exclusion.
- Completion packages stream originals sequentially into a private temporary ZIP file; known-length uploads and verification stream the archive instead of retaining hundreds of megabytes in memory. Temporary files are private and cleaned up after success or failure. PDF proof uses explicit bounded pages and image dimensions. It includes promised arrival and completion dates and can describe a completed job that required no media.
- PDF modules load their ESM dependency at render time. This fixes actual `tsx` worker startup/render failures hidden by the Next build and ESM Jest environment. Proof, invoice, report and quote PDF paths were included.
- Media reads stop at their byte limit even when upstream content length is missing. Immutable upload conflicts are consistently rejected before a large conflicting download. The 40-photo allowance is separate from a bounded ten-PDF allowance; scanned PDFs cannot consume photo slots. Documents remain quarantined until a clean scan.
- The aggregate PostgreSQL test command now refuses remote and non-test database names before executing fixture writes.
- Actual saved-template and media-recovery component journeys cover revision mismatch, retry and resource switching. They exposed an Undo control left available when the component became read-only; both the recovery control and its handler now respect the current upload permission.
- Actual communications component journeys exposed and fixed ordinary message attachments not rendering, a failed history fetch hiding already-loaded messages, and a stale updates-history error surviving a successful retry. History/cursors, unsent text and selected attachments now survive the tested failure/retry paths; late responses cannot replace another account/job's state. Mark-read failure does not block the job link.
- The repository lint gate is clean without changing its baseline or disabling rules. Cleanup removed unused code, retained typed asynchronous test behavior, and validates unknown staff scheduling responses and text-only form values instead of coercing files or unknown objects. The `.mts` runtime checks now belong to both the API typechecking and lint projects. A regression checks that passphrase whitespace is preserved and a file cannot become a text field.

## Approved additional-service implementation — September 9 continuation

The owner accepted the recommendation: extra work after a finished/paid job becomes a **new linked job**, with its own scope, schedule, price, invoice, payment and commission calculation. It does not reopen or rewrite the original bill or payout. Genuine corrections remain separate audited operations.

Implementation references:

- `apps/api/src/lib/partner-portal-v2-scheduling/service.ts`: `createPartnerAdditionalServiceDraft` starts a blank additional-work request, optionally prefilling its accessible active saved location and current contact.
